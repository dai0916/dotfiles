# done

Orca で issue から開いたワークツリー（1 issue = 1 ワークツリー = 1 ブランチ）を、出荷から後片付けまで一度に終わらせる。
**ユーザーがこのスキルを呼んだこと自体を、PJ の `AGENTS.md`「出荷手順」節に書かれた操作への承認とみなす**（節に書かれていない本番操作は、実行前に確認する）。

引数: `$ARGUMENTS`（issue 番号。省略可）

スクリプトの場所（以下 `$S`）: この SKILL.md と同じディレクトリの `scripts`（`~/.claude/skills/done/scripts` または `~/.codex/skills/done/scripts`）。

## 1. 対象を決める

- 番号：引数 → `orca worktree current --json` の `linkedIssue` → ブランチ名に含まれる `issue-N` の順
- 引数がワークツリーの issue と食い違うとき、どれからも決まらないとき、PJ の本体（`isMainWorktree: true` / 既定ブランチ）で呼ばれたときは、推測せずユーザーに聞く
- 出荷するものがこの issue の内容と合っているか確かめる。このセッションで issue を読んでいれば読み直さない（新しいコメントだけ `gh issue view N --comments` の末尾で見る）
- **対象が Epic**（`gh api repos/{owner}/{repo}/issues/N/sub_issues` が空でない）なら、ふつうは出荷するものが無い。2〜3 は飛ばして 4 へ（Epic のワークツリーにコミットがあれば、通常の issue と同じく 2〜3 を行う）
- **PR を出して止まったあとの呼び直し**（このブランチの PR が `gh pr view --json state` で `MERGED`）なら、2〜3 は飛ばして 4 へ。マージ前（`OPEN`）なら、マージを待つよう伝えて止まる

## 2. 未コミットの変更を片付ける

- `git status` と差分を見て、この issue の変更だけを stage する（関係ない変更は捨てず、報告に回す）
- commit の前にレビューを受ける。PJ にレビューの決まり（スキル・フック・`AGENTS.md`）があればそれに従う。無ければ別系統のモデルに読み取り専用でレビューさせる：
  - Claude Code から：`codex review -c model_reasoning_effort=high --uncommitted`
  - Codex から：差分を一時ファイルに書き出し（`git diff HEAD > "$d"`。未追跡の新規ファイルはパスを添える）、そのパスと観点をプロンプトにして渡す。`--allowedTools` はあとの引数をすべて取り込むので、プロンプトは `--` のあとに置く：
    `claude -p --permission-mode dontAsk --tools Read Grep Glob --allowedTools Read Grep Glob -- "<観点と差分のパス>" < /dev/null`
  - blocker / major の指摘は直して検証し、再レビューは 1 回だけ。使えないとき（上限・未ログイン）は「別系統のレビュー未実施」と報告に書く。ドキュメントだけの小さな変更は省いてよい
- commit メッセージは PJ の形式に合わせる（無ければ `<type>: <内容>（#N）`）。すでに commit 済みなら作り直さない

## 3. 出荷する

`AGENTS.md` の「出荷手順」節の **出荷** の手順を上から順に実行する。

- 節に出荷を 1 回で行うコマンドがあれば、それだけを実行する
- 節が無い PJ では、README・CONTRIBUTING・CI の設定から手順を組み立ててユーザーに一度見せ、承認を得てから実行する。あわせて、その手順を「出荷手順」節（確認 / 出荷 / 片付け）として `AGENTS.md` に足すよう提案する
- **PR を出して他の人のレビュー・マージを待つ PJ**：push して `gh pr create`（本文に `Closes #N`）まで行い、PR の URL を報告して止まる（4・5 はしない）。マージされたあとに、同じワークツリーでもう一度 `done` を呼んでもらう
- 途中で失敗したら（rebase の衝突、テストの失敗、デプロイのエラー）、そこで止めて報告する。`--no-verify`・force push・手順の読み替えはしない

## 4. issue を閉じる

`"$S/done-close.sh" N` を 1 回実行する（リリース先が既定ブランチ以外なら `--base <名前>`）。

- HEAD がリリース先に入ったか、このブランチの PR が HEAD のままリリース先にマージされた（squash でもよい）ときだけ、開いていれば「<コミット or PR> で出荷」とコメントして閉じる
- `close_status=not_shipped` なら何もしていない。3 に戻って push・マージを確かめる
- `close_status=epic_open` なら Epic に開いている子が残っている。閉じずに一覧を伝えて止まる（5 はしない）
- `close_status=error` なら内容をそのまま伝えて止まる
- 親の Epic があれば、着手できる子・前提待ちの子が出る。報告に入れ、「Orca で次の子のワークツリーを開けます」と伝える（ここでは開かない）

## 5. 報告してから片付ける

ワークツリーを消すと、このセッションのターミナルも閉じる。**先に報告を出し切ってから** 片付ける。

1. 報告：issue、コミット、出荷先と結果、実行した検証とレビュー、残した変更（あれば）、Epic の次の子（あれば）
2. 4 の `close_status` が `closed` か `already_closed` でなければ片付けずに止まる
3. 「出荷手順」節に **片付け** の手順があれば実行する（例：プレビュー環境の削除）
4. 最後に `"$S/done-cleanup.sh"` を 1 回実行する（リリース先が既定ブランチ以外なら `--base <名前>`、Orca の外で作ったワークツリーなら `--no-orca`）。スクリプトが次を確かめてから消す。`cleanup_status=error` なら理由と、それまでに消したもの（`deleted_*` の行）を伝えて止まる。`partial` ならブランチは消えたがワークツリーが残っているので、Orca から消すよう伝える
   - 未コミットの変更が無い・PJ の本体ではない・HEAD が出荷済み（4 と同じ判定をやり直す）
   - リモートのブランチが残っていれば、その先端が HEAD か、変更がすべてリリース先に入っているときだけ、確かめた先端から動いていないことを条件に消す
   - ローカルのブランチ → Orca のワークツリーの順に消す（ワークツリーを消すとこのターミナルも閉じる）
