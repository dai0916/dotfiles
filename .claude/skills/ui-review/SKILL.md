あなたは `/ui-review` スキルを実行しています。
Playwright でスクリーンショットを撮影し、**4つの専門エージェント**による自律レビュー → 設計 → 実装 → 再レビューのサイクルを回してください。

引数: `$ARGUMENTS`

---

## Phase 0: セットアップ

### 対象 URL の決定

優先順位:
1. コマンド引数の第1引数が URL なら使用
2. `package.json` の `dev` スクリプトからポートを検出し `http://localhost:<port>` を使用
3. デフォルト: `http://localhost:3000`

### ページ一覧

- `--pages "/,/about,/settings"` が指定されていればそれを使用
- なければ `/` のみ

### サイクル数

- `--cycles N` が指定されていればその回数（デフォルト: 2）
- 各サイクルで「撮影 → レビュー → 設計 → 実装 → 再撮影」を繰り返す

### Playwright 確認

```bash
# playwright がインストールされているか確認
npx playwright --version 2>/dev/null || npm install -D playwright
npx playwright install chromium 2>/dev/null
```

### dev サーバー確認

対象 URL に対して `curl -s -o /dev/null -w "%{http_code}" <URL>` でアクセス可能か確認する。
起動していなければユーザーに `npm run dev` を依頼する。

## Phase 2: 並列レビュー（4エージェント）

以下の **4つのエージェントを並列で起動**する（1つの message に4つの Agent tool call）。

### Agent 1: ビジュアルデザイン・レビューアー

```
あなたはビジュアルデザインの専門家です。以下のスクリーンショットを確認し、改善点をフィードバックしてください。

スクリーンショット:
- /tmp/ui-review-screenshots/desktop-light-full.png
- /tmp/ui-review-screenshots/desktop-dark-full.png
- /tmp/ui-review-screenshots/mobile-light-full.png

チェックポイント:

【レイアウト・構造】
- グリッドの整列は正確か（カラム幅、ガター幅の一貫性）
- カード/セクション間の余白は均一か
- 並列カードの高さは揃っているか
- コンテンツの最大幅は適切か（読みやすい行長か）
- ファーストビューの情報量は適切か（多すぎ/少なすぎ）

【タイポグラフィ】
- フォントサイズの階層は明確か（H1 > H2 > body > caption）
- 見出しが本文に埋もれていないか
- 行間・文字間は読みやすいか
- 数値の視認性（太字・サイズ・色で強調されているか）

【カラー】
- カラーパレットの一貫性（同じ意味には同じ色を使っているか）
- 色に意味的な根拠があるか（成功=緑, 警告=黄, エラー=赤 等）
- ダークモードでのコントラスト比（WCAG AA 4.5:1 以上か）
- ダークモードでのカード境界の視認性

【ビジュアルの質】
- プレースホルダー/空状態は美しいか
- アイコンのスタイル統一性（絵文字 vs SVG の混在はないか）
- プログレスバー・チャートの視覚的な明瞭さ

以下のフォーマットで回答する（4人の結果を Phase 3 で統合するため）:
## 良い点
## 問題点（P0: 致命的 / P1: 重要 / P2: 改善推奨）
各問題には「対象コンポーネント」「現象」「改善提案」を含めること。
コードは書かない。レビューコメントのみ。
```

### Agent 2: 情報設計・UX レビューアー

```
あなたは情報設計とUXの専門家です。以下のスクリーンショットを確認し、改善点をフィードバックしてください。

スクリーンショット:
- /tmp/ui-review-screenshots/desktop-light-full.png
- /tmp/ui-review-screenshots/desktop-light-fold.png
- /tmp/ui-review-screenshots/mobile-light-full.png

チェックポイント:

【情報の優先度】
- ファーストビューに最も重要な情報があるか
- ユーザーの日常行動に直結する情報が上部にあるか
  （管理者情報 vs ユーザー情報の区別）
- 「0件」「100%」など情報量ゼロの表示がスペースを占有していないか
- データの変化を追える表示があるか（前回比、トレンド等）

【データの表示方法】
- 数値はバーチャート/テーブル/カード等、最適な形式で表示されているか
- バーチャートの数値レンジは意味のある差を表現できているか
- ラベルは平易でユーザーが理解できるか（技術用語は避けているか）
- 単位・母数・対象期間は明示されているか

【ナビゲーション・導線】
- クリック可能な要素は明確にわかるか
- 空状態/エラー状態に適切な案内があるか
- セクション間の論理的な流れは自然か

【モバイルUX】
- スクロール量は適切か（過度に長くないか）
- タップターゲットのサイズは十分か（最低44x44px）
- コンテンツの優先度がモバイルレイアウトに反映されているか
- 折りたたみ/省略すべきセクションはないか

【言語・ローカライゼーション】
- UI言語は統一されているか（英語と日本語の混在はないか）
- 日付フォーマットはロケールに合っているか
- データ由来の文言とUIラベルの言語が一致しているか

以下のフォーマットで回答する（4人の結果を Phase 3 で統合するため）:
## 良い点
## 問題点（P0 / P1 / P2）
各問題には「対象コンポーネント/セクション」「現象」「改善提案」を含めること。
コードは書かない。
```

### Agent 3: アクセシビリティ・レビューアー

```
あなたはWebアクセシビリティの専門家です。以下のスクリーンショットとソースコードを確認し、改善点をフィードバックしてください。

スクリーンショット:
- /tmp/ui-review-screenshots/desktop-light-full.png
- /tmp/ui-review-screenshots/desktop-dark-full.png
- /tmp/ui-review-screenshots/mobile-light-full.png

また、ソースコードも確認してください。プロジェクトのコンポーネントディレクトリを Glob/Read で探索し、以下を確認:

チェックポイント:

【コントラスト・可読性】
- テキストと背景のコントラスト比（WCAG AA: 通常テキスト 4.5:1, 大テキスト 3:1）
- ダークモードでの淡いテキスト（zinc-400, zinc-500等）の可読性
- 小さいフォントサイズ（10px, 11px 等）の視認性
- プログレスバーのセグメント境界の区別

【セマンティクス】
- 見出しレベルの適切さ（h1 > h2 > h3 が論理的に正しいか）
- ランドマーク要素（main, nav, section, aside）の適切な使用
- リストはol/ulで表現されているか（div の羅列になっていないか）
- imgタグに適切な alt テキストがあるか

【インタラクション】
- キーボードフォーカスが可視化されるか（focus-visible スタイル）
- details/summary の操作はアクセシブルか
- リンク/ボタンの区別は明確か
- ホバーに依存する重要な情報がないか（tooltip のみの情報等）

【スクリーンリーダー】
- 装飾アイコン（絵文字含む）に aria-hidden が付いているか
- プログレスバーに role="progressbar" と aria-valuenow があるか
- 統計カードの関連情報がグループ化されているか

以下のフォーマットで回答する（4人の結果を Phase 3 で統合するため）:
## 良い点
## 問題点（P0 / P1 / P2）
各問題には「対象箇所」「WCAG基準」「改善提案」を含めること。
コードは書かない。
```

### Agent 4: レスポンシブ・クロスブラウザ レビューアー

```
あなたはレスポンシブデザインの専門家です。以下のスクリーンショットを確認し、改善点をフィードバックしてください。

スクリーンショット:
- /tmp/ui-review-screenshots/desktop-light-full.png
- /tmp/ui-review-screenshots/desktop-light-fold.png
- /tmp/ui-review-screenshots/mobile-light-full.png
- /tmp/ui-review-screenshots/mobile-light-fold.png
- /tmp/ui-review-screenshots/mobile-dark-full.png

チェックポイント:

【ブレークポイント】
- sm/md/lg での切り替えは適切か
- カードのカラム数はビューポートに合っているか
- テキストが折り返しや切り詰めで読めなくなっていないか
- テーブル/リストがモバイルで横スクロールを強制していないか

【モバイルファースト】
- モバイルで最も重要な情報が最上部にあるか
- タップターゲットは十分な大きさか（44x44px 以上）
- スクロール深度は適切か（重要な情報への到達コスト）
- 横方向のパディングは十分か（エッジからの距離）

【デスクトップ活用】
- ワイドスクリーンでの余白は適切か（max-width 制限）
- 2カラム/3カラムレイアウトで空間を有効活用しているか
- ホバーエフェクトは一貫性があるか

【コンポーネント別チェック】
- カードの最小幅は確保されているか（テキストが潰れないか）
- プログレスバーのセグメントはモバイルでも識別可能か
- チャートやグラフの値はモバイルでも読み取れるか
- ランキングリストのトランケーションは自然か

以下のフォーマットで回答する（4人の結果を Phase 3 で統合するため）:
## 良い点
## 問題点（P0 / P1 / P2）
各問題には「対象」「ビューポート」「現象」「改善提案」を含めること。
コードは書かない。
```

## Phase 3: フィードバック統合 & 設計

4つのレビュー結果を受け取ったら、**設計エージェント（Plan タイプ）** を起動する:

```
あなたはフロントエンド設計者です。4つのレビューエージェントからのフィードバックを統合し、
実装計画を作成してください。

## レビュー結果
（ここに4つのレビュー結果をすべて貼り付ける）

## 設計の要件
1. P0 の問題はすべて解決すること
2. P1 は可能な限り解決すること
3. P2 は実装コストが低いもののみ含めること
4. 既存コードの構造を尊重し、最小限の変更で最大の効果を得ること
5. バックエンド変更が不要な方法を優先すること

## アウトプット
1. 変更するファイル一覧（パスと変更概要）
2. 各変更の具体的な内容（何をどう変えるか）
3. 実装の優先順序
4. 変更しないと判断した指摘事項とその理由
```

---

## Phase 4: 実装

設計エージェントの出力に従い、あなた（メインエージェント）が実装する。

実装ルール:
1. 1ファイルずつ変更し、変更のたびにファイルの整合性を確認する
2. 新規コンポーネントが必要な場合は既存コンポーネントのスタイルに合わせる
3. `npm run build` でビルドエラーがないことを確認する
4. 不要になったコンポーネント/ファイルは削除する

---

## Phase 5: 再撮影 & 検証

```bash
node ~/.claude/skills/ui-review/scripts/screenshot.mjs \
  "<TARGET_URL>" \
  /tmp/ui-review-screenshots \
  --pages "<PAGES>"
```

撮影後、スクリーンショットを Read ツールで確認し:

1. P0 の問題がすべて解消されているか
2. 新たなレグレッション（レイアウト崩れ等）がないか
3. ダークモード・モバイルで問題がないか

問題がなければ次のサイクルへ。問題があれば修正してから再撮影。

---

## サイクル繰り返し

指定されたサイクル数まで Phase 1〜5 を繰り返す。
2 サイクル目以降は、前サイクルで解消済みの指摘は除外し、**新たな改善点に集中**する。
