# Global Vibe Coding Baseline

このファイルは Codex のグローバル既定指示である。すべてのリポジトリで適用する。
リポジトリまたは作業ディレクトリにある `AGENTS.md` / `AGENTS.override.md` は、フレームワーク、ディレクトリ構成、検証、セキュリティ、リリース手順などのローカル要件について本ファイルより優先する。本ファイルはそれらを置き換えず、矛盾しない限りベースラインとして併用する。

## モデルの使い分け

作業に必要な最小のモデルと reasoning を選ぶ。大きな生ログ・巨大ファイル・探索結果を上位モデルへそのまま渡さず、まず Luna で要点、失敗箇所、再現手順、関連パスへ圧縮する。

| 層 | モデル / reasoning | 主な用途 |
| --- | --- | --- |
| Luna | `gpt-6-luna` / low〜medium | ファイル探索、grep 結果やログ・テスト失敗の要約と圧縮、コミットメッセージ、定型コード |
| Sol | `gpt-6.1-sol` / medium（設計・RCA・レビューは high） | 既定。実装、リファクタリング、テスト、設計、実装計画への分解、根本原因分析、クロスレビュー |
| Astra | `gpt-6-astra` / 既定 | 6.1 Sol（high）でも手詰まりの問題だけ。単発で使う（6.1 Sol はコーディングで Astra にほぼ並び、料金は約 1/5） |

- 最初から Astra を選ばない。高速枠（Ultrafast）も使わない。最小の再現例と圧縮済みの証拠だけを渡す。
- ユーザーの明示指定、利用可能性、ローカルの `AGENTS.md` がある場合はそれらを優先する。
- サブエージェントに分けるときも、各担当は上の役割に合うモデルを使う。

## 完了条件

変更に比例したテスト・lint・型検査を実行し、実行したコマンドと結果を報告する。受け取った計画に完了条件が書かれていれば、それを満たすまで止まらない。満たせない場合は、何が妨げているかを書いて止まる。

## 行き詰まったとき

- 同じ問題の修正が 2 回失敗したら、力任せの追加修正を止める。再現条件、観測事実、試行履歴、根本原因の仮説、次の安全な実験を整理し、Sol（high）で見直す。
- それでも解けなければ、最小再現に切り出して Astra に一度だけ渡すか、Claude への引き継ぎをユーザーに提案する。

## 完了前のクロスレビュー

- コード変更をコミット・push・デプロイして完了する前に、**Claude（別系統のモデル）による読み取り専用のレビュー**を受ける。PJ に `cross-review` スキルがあればそれに従う。
- Claude が使えないとき（利用上限・未ログインなど）は、新しい Codex コンテキストでの読み取り専用レビューで代える。その場合は「Claude レビュー未実施」と報告に明記する。
- 仕様・設計書との整合、データ更新の根拠、API 契約、ページング・状態遷移、既存の未コミット変更との混在を優先的に確認する。
- blocker / major の指摘があれば修正・検証してから、再レビューを 1 回だけ行う。それ以上は繰り返さず、残った指摘をユーザーに報告する。
- ユーザーが明示的にレビューを省略した場合と、ドキュメントだけの小さな変更は対象外。

## コンテキストとセッション

- 機能完了、調査完了、レビュー完了などの節目ごとに、「確定仕様」「変更点」「検証結果」「残タスク・未解決リスク」を短く要約する。大きな区切りの後は、その要約を引き継ぎにして新しいセッションを始めることを勧める。
- 生ログは必要箇所・エラーの先頭と末尾・関連スタックトレースへ絞り、原文全量を後続フェーズへ持ち込まない。

## ローカル設定との共存

- プロジェクトルートの `AGENTS.md` は、技術スタック、ディレクトリ規約、コマンド、品質基準、運用制約を記載する場所とする。
- グローバル方針とローカル方針が両立する場合は両方に従う。衝突する場合は、より近いディレクトリのローカル方針、ユーザーの明示指示、セキュリティ・安全要件を優先する。
- 一時的にグローバル方針自体を置換する必要がある場合のみ、`~/.codex/AGENTS.override.md` を使用し、完了後に削除して通常のベースラインへ戻す。
